# 08 · 美术流程验证（1 角色 + 1 场景 + 1 UI）

> 状态：草案。目的不是做出最终美术，而是回答三个问题：**流程跑不跑得通、单个资源要花多少时间和钱、在目标设备上跑不跑得动**。
> 前提：风格按 04 §3 / §6，山海经 × 古器物棋子，**卡通风格化**（2026-10-06 定，不走写实）。如果概念图阶段否掉这个方向，就换风格重跑概念阶段，后面的步骤不变。

## 0. 先定的东西

- **目标平台和基准机型**：iOS + Android + Windows（ADR-009），基准机型见 §6。
- **镜头**：固定俯视斜角（04 §2），所有验收截图都用这个镜头，不用特写来骗自己。

## 1. 角色：狰（四足异兽）

《西山经》：章莪之山「有兽焉，其状如赤豹，五尾一角」。

选它的理由：
- 四足，验证非人形骨骼的真实成本（04 §6 的最大风险）。
- 五条尾巴是次级动画（骨骼链或物理）的压力测试。
- 形象简单好认，不会在造型上耗太久。

| 交付物 | 内容 |
|---|---|
| 概念图 | 3 张：器物态（静止的棋子）、活体态、两者之间的过渡 |
| 模型 | 先试 AI 图生 3D 出粗模，再人工修拓扑和 UV；记录 AI 能省多少 |
| 材质 | 两套：器物态（如青铜）、活体态；再做一个换材质的费用档位变体（陶 / 玉） |
| 骨骼 | 四足骨骼 + 尾巴骨骼链，作为「四足家族」的标准骨骼 |
| 动作 | 待机、攻击、施法、受击、死亡，加上「器物活过来」的觉醒动作 |
| 特效 | 1 个战法特效、1 个「胡牌」成型特效 |

**进度**

- 2026-10-06 概念图第 1 轮完成：器物态、活体态、过渡态各 1 张，用 Mistral 出图（流程沿用 standing，脚本在 `tools/art/`）。结果、提示词和经验见 `art/zheng/concept/README.md`。
- 2026-10-06 Tripo API 试验：图生 3D 可用（2 万面带 PBR，$0.30/次，概念图需去掉底座）；自动绑定给五尾都建了骨骼链，但头、腿、尾识别错乱，walk 预设因此错位；非人形只有 walk 一个预设动作。结论：模型用 Tripo，骨骼修正和 6 个动作要进 Blender。记录见 `art/zheng/model/README.md`。
- 2026-10-06 风格改为卡通（04 §3）：第 1 轮写实概念图和 Tripo 模型只作流程参考，概念图按卡通风格重出（第 2 轮，`art/zheng/concept/r2/`）。Blender 5.2 已装，用于修骨骼和做动作；模型文件（glb / fbx / blend）走 Git LFS。
- 2026-10-06 卡通版跑通到 FBX：器物态概念图（`concept/r2/artifact_v1.png`）→ Tripo 图生 3D（30 积分）→ Blender 脚本绑定（39 骨，四足 + 五尾链，体素代理算自动权重）→ 程序化 6 个动作 → FBX 进 `client/Assets/HotRes/Art/Zheng/`。脚本在 `tools/art/blender/`，过程和坑见 `art/zheng/model/README.md`。Unity 侧已跑通：导入规则（Generic、动作名、idle 循环）、`Relics/Toon` 卡通着色 + 描边、无头截图脚本（`Batch.ArtPreviewZheng`），截图 `art/zheng/model/zheng_unity.sheet.png`。
- 2026-10-06 胡须已删（绑定脚本自动识别细长突出物）。材质 5 套：费用档位陶 / 青铜 / 玉 / 金 + 活体态，全部共用一张青铜贴图，靠 `Relics/Toon` 的「重着色」参数区分（贴图只提供明暗细节和铜绿斑点遮罩），尾巴和角用顶点色遮罩单独上色，活体态尾巴是发光的火焰渐变。换档位只改材质参数、不换贴图，正好用于热更验证。对比图 `art/zheng/model/zheng_variants.png`，活体态动作 `zheng_living.sheet.png`。

## 2. 场景：一块棋盘

- 一个方位的「山海舆图」棋盘，带地貌（如西山：山岩、赤色调）。
- 包含 8 人对局里一块棋盘的完整元素：格子、备战席、双方站位区、光照、后处理。
- 在棋盘上**放满单位**（狰复制若干个，换材质区分敌我）测性能和可读性，而不是只放一个。

## 3. UI：商店 + 听牌提示

选这块是因为它直接承载核心乐趣（06）：
- 5 张卡的商店，卡面上能看出费用档位（材质）。
- 「听牌」提示：差哪张、池中还剩几张。
- 买到最后一张时的「胡牌」演出：UI 动效加上 §1 的成型特效联动。
- 同时定下 UI 的视觉语言（字体、边框、图标风格），后续 UI 都按这个来。

## 4. 验收标准

| 项 | 标准 |
|---|---|
| 可读性 | 在战斗镜头下，放满单位时仍能一眼看出：敌我、费用档位、谁在行动 |
| 性能 | 基准机型（§6）上满棋盘稳定帧率：移动端 30（目标 60）、PC 60；记录 draw call、面数、内存、发热 |
| 热更 | 改材质、改 UI 文案、换特效，只发热更包就能生效（07 §7） |
| 成本 | 记录每一步的工时和外包或工具费用，换算出「一个四足角色的完整成本」 |
| 流程文档 | 每一步的工具、参数、提示词都归档，后续角色照做 |

## 5. 产出给后续决策用

- 四足家族的成本 → 决定异兽和人形角色的比例（04 §6）。
- 性能数据 → 决定移动端是否可行，或者需要做多少降级。
- 风格的实际效果 → 决定是否锁定「古器物棋子」方向。

## 6. 基准机型（提议，按目标市场再调）

| 档位 | iOS | Android | Windows |
|---|---|---|---|
| 最低支持 | A13（iPhone 11） | 骁龙 6 系 / 天玑 7 系，4GB 内存 | 核显（Iris Xe 级） |
| 主力 | A15（iPhone 13） | 骁龙 7 系，6GB 内存 | GTX 1060 级 |

- 美术预算按**最低支持档**定，PC 和高端机只开更高的画质档位（URP 质量分级）。
- 验证阶段至少测：1 台最低档安卓、1 台最低档 iPhone、1 台 PC。
- 屏幕比例要覆盖：手机 19.5:9、iPad 4:3、PC 16:9。棋盘和商店 UI 在三种比例下都要验收。
