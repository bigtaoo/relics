# 06 · 牌型系统（核心乐趣：凑牌 → 胡牌）

> 状态：讨论中。第一阶段仍照搬三战的缘分（ADR-006），本文是第二阶段差异化的方向，但**接口要在第一阶段就预留**（见 §5）。

## 1. 麻将的快感从哪来

| 麻将里的来源 | 对应到自走棋 |
|---|---|
| **听牌的紧张感**：差一张，知道要等哪几张 | 「听牌」状态可见：明确告诉玩家差哪几张、各自还剩几张 |
| **数得清的概率**：别人打出的牌是公开的，可以算还剩几张 | 共享卡池 + 他人阵容公开，显示每张牌在池中的余量 |
| **番型分档**：越难凑的牌型番数越高 | 牌型分档：小牌型稳定、大牌型罕见但收益极高 |
| **胡牌那一刻**：推倒、亮牌、报番 | 成型时刻要有专门的仪式，而且要比普通升星强烈得多 |
| **取舍**：拆搭子改听、放弃大牌求快 | 转型成本可控：卖牌返还够高，让「改听」成为真实选项 |
| **被截胡** | 8 人共享卡池里，别人买走你听的最后一张，要能让玩家感知到 |

结论：快感 = **预期（听牌） × 不确定性（还剩几张） × 兑现（胡牌仪式）**。三项缺一项都会变弱。尤其是「预期」：玩家要清楚知道自己离胡牌还差什么。

## 2. 两次兑现

自走棋和麻将不同，凑齐牌型和真正打出效果不在同一时刻，所以要设计两次兑现：

1. **准备阶段的「胡牌」**：最后一张买进来的瞬间。亮牌、报出牌型名、全场（其他 7 人）可见的播报。这是确定的快感，不依赖战斗结果。
2. **战斗阶段的「发动」**：牌型效果在对应阶段爆发（呼应 00 中「不同定位在不同阶段强」）。演出停顿 tick 写进逻辑时间轴（01 §3.1）。

## 3. 牌型分档（草案，用于讨论）

| 档位 | 难度 | 目标感受 | 设计约束 |
|---|---|---|---|
| 小牌型 | 每局都能凑出 1～2 个 | 稳定、有方向感 | 等同于普通缘分 |
| 中牌型 | 几局一次 | 次优阵容能稳进前四 | 与小牌型共用核心棋子 |
| 役满（大牌型） | 约十局一次 | 翻盘、碾压、录屏分享 | 需要特定组合 + 运气；**全服播报** |

- 役满不能强到「凑齐就必胜」，否则对局会变成纯运气。要保留克制关系（00 中的克制环）。
- 牌型之间要能复合（像「清一色 + 对对胡」那样叠番），复合的结算规则必须与顺序无关（03 §5）。

## 4. 与世界观的结合

见 04 §6。如果采用山海经，五藏山经的「南、西、北、东、中」五方，恰好对应麻将的风牌「东南西北」+「中」，可以直接作为阵营与牌型的骨架。

## 5. 第一阶段需要预留的接口

- **牌型判定独立成模块**：输入阵容（棋子 id + 星级 + 站位），输出命中的牌型列表。纯函数、确定性、在 Core 中，服务端和客户端共用。
- **听牌计算**：输入阵容 + 候选牌，输出「再加哪张就能成型」。只用公开信息计算（卡池余量由服务端下发公开部分），不泄露商店内容。
- **事件**：`HandFormed`（准备阶段胡牌）与 `HandTriggered`（战斗中发动）分开，供演出层使用。
- 三战的缘分在第一阶段就走这套模块实现，换成自有牌型时只换数据。

## 6. 待定

- 卡池余量是否对所有人公开（麻将式算牌 vs. 信息隐藏）
- 胡牌播报是否让对手看到具体牌型（信息博弈）
- 牌型数量与每档的具体效果，等三战缘分还原后再设计
