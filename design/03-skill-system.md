# 03 · 战法 / 效果框架

> 状态：草案。funny 和 daydayup 都没有通用的效果框架，这是本项目新增的核心工作。
> 目标：三战的每一条战法都能**只靠数据表达**，换皮时只改数据，不改代码。

## 1. 基本模型

```
战法 Skill = {
  id, kind: 被动 | 指挥 | 主动 | 普攻 | 追击 | 缘分,
  trigger: 触发时机,
  conditions: [条件...],
  chance: FP (发动概率),
  prepTurns: 准备回合数（如有）,
  effects: [ { target: 目标选择器, effect: 效果, params } ... ]
}
```

战法中的特殊行为一律写成**带标签的字段**，不用闭包或回调。这条沿用 daydayup 的约定：数据可以序列化、比较，也可以生成说明文字。

## 2. 触发时机（初版，按三战还原时再补全）

战斗开始、阶段开始（指挥 / 决战）、回合开始、自身行动前 / 后、普攻前 / 后、造成伤害后、受到伤害后、兵力低于阈值、友军阵亡、敌军阵亡、回合结束。

## 3. 目标选择器

自身、友军（全体 / 随机 N 人 / 兵力最低 / 前排）、敌军（全体 / 随机 N～M 人 / 兵力最低 / 对位 / 前排）、伤害来源。
**随机选取一律通过 targeting Prng 流**，并且只在确实需要随机时才抽。

## 4. 效果原语

| 类别 | 原语 |
|---|---|
| 伤害 | 兵刃伤害（伤害率）、谋略伤害（伤害率）、真实伤害、持续伤害 |
| 恢复 | 治疗（恢复率）、吸血 |
| 属性 | 属性增减（值 / 百分比）、造成伤害增减、受到伤害增减 |
| 控制 | 震慑（无法行动）、缴械（无法普攻）、计穷（无法发动主动战法）、混乱 |
| 护盾 | 护盾值、抵挡次数 |
| 状态操作 | 驱散、净化、免疫、延长 / 缩短持续时间 |
| 叠层 | 叠层、按层数缩放、满层触发 |
| 战场 | 改变行动顺序、额外行动、追击 |
| 资源 | 读取 / 消耗金币（三演的金币机制） |

## 5. 状态（Buff）规则

需要明确的规则：同名状态是刷新、叠加还是取最大值；不同来源能否共存；持续时间按「回合」还是按「自身行动次数」计算。
**以三战的实测为准**，在 02 中补全后回填到这里。

计算顺序要与插入顺序无关：同类加成先求和、再截断（沿用 daydayup runbuffs 的做法），避免结果依赖状态的插入顺序。

## 6. 结算顺序

同一触发时机下有多个战法时：按站位行动顺序 → 战法类别（被动 → 指挥 → 主动 → 普攻 → 追击）→ 战法槽位。顺序固定，并有测试锁定。

## 7. 数据存放

- 第一阶段：战法写成 C# 记录（与 funny ADR-001「数值写在代码里」一致），按人类可读的单位编写，例如 `Percent(125)`，在加载时一次性转换成 FP。
- 另外提供一份可读的导出（例如 Markdown 表），方便与截图逐条核对。
- 是否改用表格（Excel → JSON），等战法数量上去之后再决定。

## 8. 演出接口

Core 只输出**事件流**，例如「A 对 B 发动战法 X」「B 受到 120 点兵刃伤害」「B 获得护盾」，每条事件带 tick。
Unity 演出层只消费事件，不反向调用 Core。
