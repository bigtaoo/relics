# 棋盘场景验证（08 §2）

生成：`unity run client -- -executeMethod Automatic.Editor.Batch.BoardSlice`

- 脚本：`client/Assets/Editor/BoardSlice.cs` 负责单位、镜头、截图和统计，`BoardDressing.cs` 负责棋盘、地貌、灯光和后处理。所有贴图和网格都由脚本生成，重跑时原地覆盖，GUID 不变。
- 场景：`client/Assets/HotRes/Scenes/board_west.unity`，在热更资源目录里。场景单独放一个目录，因为 YooAsset 不能把场景和普通资源打进同一个包。
- 截图：`phone_19.5x9.png`、`pad_4x3.png`、`pc_16x9.png`，三种比例都用同一个战斗镜头（俯角 50°，FOV 30），镜头自动拉远到整张桌面都能放进画面。

## 2026-10-06 第 1 版

**布局（临时）**：每方 3 排 × 5 列，中间一条「河」（象棋棋盘的做法），每方再加 8 格备战席。三演的真实行列数还没截图确认（02 §3），这些数字都是 `BoardLayout` 里的常量，确认后改常量就行。

**画面**：
- 桌面做成「山海舆图」：一张生成的纸面贴图，墨线画格子，己方半场冷色、敌方半场暖色，格子棋盘格交错。
- 地面是带等高线的旧地图，西山用红岩低多边形山。
- 后处理：泛光、饱和度和对比度调整、暗角。

**单位**：
- 46 只狰，两边的格子和备战席全部放满（最坏情况）。档位随机，偏向低档。
- 敌我靠两样区分：底座颜色（蓝 / 红）和血条颜色（绿 / 红）。
- 正在行动的单位：活体态，摆攻击姿势，脚下有一个发光金环。

**可读性结论**：
- 敌我：清楚。
- 谁在行动：金环能看出来，但不够醒目，正式版还要配合镜头或特效。
- 单位要侧转 40° 朝向对面。正对或背对镜头时，四足兽从俯视角看只是一团，侧过来才看得出身体轮廓。
- 青铜、玉、金：能分开。
- **陶和活体态撞色**：都是橙红色加深色斑点，行动单位只能靠金环认出来。陶也和敌方的红色底座混在一起。建议把陶改成灰陶或白陶。还有一个设计问题要先定：战斗中单位是否都「活过来」？如果是，战斗中就看不出档位了。
- **手机 19.5:9 下单位偏小**：整张桌面（含两边备战席）都要放进画面，高度决定了缩放，左右两边空出很多。需要决定手机上的取景：裁掉对方备战席，或者镜头推近、允许拖动。

**性能（静态数据）**：
- 单位：46 个蒙皮网格，**88.3 万三角面**（单只 1.92 万面，Tripo 输出原样），1794 根骨骼。
- 场景其余部分：166 个静态渲染器、5.8 千三角面。材质 16 个。
- 编辑器里在这台 PC 上渲染约 4–5 ms/帧，**这不是设备数据**。
- 结论：单只面数要降到约 3–5 千（移动端满场 15–25 万面），这一步要先做减面或 LOD 再上真机。描边是第二遍绘制，等于每只单位的顶点再处理一遍，算预算时要算进去。
- 真机帧率还没测：需要把场景接进热更入口，打包到基准机型上跑。

## 2026-10-06 减面后

狰减到单只 3000 面（见 `art/zheng/model/README.md`），满场蒙皮网格 **13.8 万面**（原来 88.3 万），整个场景 14.4 万面，在移动端约 20 万面的预算内。截图已更新，在战斗镜头下和减面前看不出区别。真机帧率还没测。

## 2026-10-06 Windows 真机帧率

做法：热更层的 `BoardBench`，用启动参数 `-bench` 触发。通过 YooAsset 从资源包加载 `board_west` 场景，跟正式热更走同一条路径。关掉垂直同步，热身 3 秒后测 10 秒。命令见 `client/README.md`。

| 机器 | 分辨率 | 平均帧时间 | 中位 | p99 | GPU | batches / SetPass / 三角面 |
|---|---|---|---|---|---|---|
| Core Ultra 7 165H + Intel Arc 核显（开发本） | 1920×1080 窗口 | 1.76 ms（569 fps） | 1.66 ms | 2.97 ms | 1.47 ms | 444 / 234 / 43 万 |

- 满场 46 只、3000 面，在核显上也远超 PC 目标 60 fps，有 9 倍以上的余量。最低档 Iris Xe 大约是 Arc 核显的一半性能，推算仍在 200 fps 以上，没有实测。
- 实际提交的三角面是 43 万，约为模型面数的 3 倍：每只单位要画三遍，正常着色、描边、阴影。
- SetPass 234 偏高（共 16 个材质），PC 上无所谓。上移动端前值得看一下 SRP Batcher 的合批情况。
- 移动端没测（用户决定先只测 Windows）。热更路径只做到「理论上通过」：场景能从资源包加载，但没有单独验证「只发热更包就能换场景」。

## 2026-10-06 只有成型的棋子活过来

两项决定（04 §2、§6）落到场景里：
- 陶改成灰陶。
- 场景改成战斗阶段的样子：**只有成型的棋子是活体态**。己方 5 只（`FxTimeline.HandCells`，跟胡牌演出同一组），敌方 3 只。其余全是器物态，行动单位也一样，脚下的金环照旧。
- 单位根节点名带上档位（`Unit pottery` 等），准备阶段和胡牌演出靠它把成型的棋子先换回档位材质。

**可读性结论**：
- 活体态（橙红身体、火焰尾巴）在整桌镜头里很跳，成型的一组一眼能看出来，敌方的也是。
- 没成型的棋子能分出档位：灰陶、青铜、玉、金。灰陶在泛光下偏白，和活体、红色底座都不撞了。
- 金和活体靠身体颜色区分（金是通体亮黄，活体是橙红加黑斑），没有混淆。
- 行动单位现在是器物态，只靠金环认，比以前更不醒目。这个本来就要靠镜头和特效解决（见第 1 版结论）。

面数和材质数没变（13.8 万面，16 个材质）。

打包时发现的坑：YooAsset 按文件名寻址（`AddressByFileName`），同一个目录里同名不同扩展名的资源会冲突，例如 `board_ground.png`、`.asset`、`.mat`，以及 `zheng.fbx` 和 `zheng.controller`。生成脚本现在给网格加 `_mesh` 后缀、给贴图加 `_tex` 后缀，动画控制器改名为 `zheng_anim.controller`。

## 2026-10-07 热更验收（08 §4）

验收项「改材质、改 UI 文案、换特效，只发热更包就能生效」在 Windows 包上跑通。`Relics.exe` 不重打，只跑 `Batch.BuildHotUpdate`，用 `-autoplay` 在同一时间点截图对比，见 `hot_update_check.png`（左边改之前，右边改之后；上排 0.0 s，下排 1.9 s）。

| 改动 | 文件 | 结果 |
|---|---|---|
| 材质 | `zheng_jade.mat` 的 `_BodyColor` 改成紫色 | 玉档棋子身体变紫，尾巴（单独的颜色参数）不变 |
| UI 文案 | `ui_shop.prefab` 回合栏「准备」改成「热更测试」 | 生效 |
| 特效 | `fx_hu_piece.prefab` 光柱的 `startColor` 改成青色 | 胡牌时的光柱变青 |

版本和下载量：

| 版本 | 内容 | 启动时下载 |
|---|---|---|
| 0.1.0.9 | 三项一起改（第一次改的是印，后面换成光柱） | 3 个包，2064 KB：狰 1743 KB、UI 179 KB、特效 192 KB |
| 0.1.0.10 | 只换特效 | 1 个包，187 KB |
| 0.1.0.11 | 全部改回去 | 0：包名是内容哈希，旧包还在本地缓存里 |

结论和坑：
- ~~**改一个材质参数要重下整个狰的包（1.7 MB）**~~：YooAsset 按目录打包，材质和 FBX、贴图在同一个包里。→ 已改，材质和贴图单独打包，见下面「材质单独打包」。
- 回滚就是往前发一版旧内容（发布护栏不允许版本号倒退），玩家本地有旧包缓存时不用下载。
- 卡面头像是渲染好的贴图，不跟着材质变。改档位颜色要同时重渲头像（`Batch.UiSlice`）。
- 胡牌的「山海印」特效被 UI 的「胡」字大印盖住，截图里看不到，所以特效改动用光柱来验证。
- 回合栏文字在开战时由热更代码把「准备」替换成「战斗」（`HuShowUi`），改了文案就替换不到了。正式的 UI 文案应该由代码按状态填，不写死在预制体里。

### 材质单独打包（同日）

打包规则从 `PackDirectory` 换成自定义的 `PackDirectoryMaterialsApart`（`client/Assets/Editor/MaterialPackRule.cs`）：仍按目录打包，但每个目录里的 `.mat` 单独成一个 `<目录>_materials` 包，贴图单独成一个 `<目录>_textures` 包。

- 只拆材质时，特效目录会出现循环依赖：预制体引用材质，材质又引用同目录的贴图。所以贴图也一起拆，依赖变成单向的：模型、预制体、场景 → 材质 → 贴图。
- 狰的 1.7 MB 拆成：模型和动作 285 KB、贴图 1458 KB、材质 3 KB。棋盘、特效、UI 也一样拆开。

| 版本 | 内容 | 启动时下载 |
|---|---|---|
| 0.1.0.13 | 新布局（中间的 0.1.0.12 是只拆材质的那版，作废） | 16 个文件，6932 KB：布局变了，所有包都要重下一次 |
| 0.1.0.14 | 玉材质改紫 | **1 个文件，3 KB**（拆包前 1743 KB），玉档棋子变紫 |
| 0.1.0.15 | 改回去 | 0，和 0.1.0.13 的包完全相同 |

- 引用材质的包（狰的模型包、场景包）在材质改动后包内容不变，只有材质包变。
- 拆包前后同一时间点的截图差异和拆包前两次同内容运行之间的差异一样（约 5% 像素，来自待机相位和粒子），画面没变。
- 贴图现在是狰最大的一块（1.46 MB），只改贴图也不用重下模型和动作。
